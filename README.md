# 미션 3 - Mini NPU 패턴 판별 프로그램


간단한 **Mini NPU Simulator** 프로그램입니다.  
이 프로그램은 패턴 행렬과 필터 행렬 사이의 **MAC 연산(Multiply-Accumulate, 곱셈-누산 연산)** 을 수행하여,  
입력 패턴이 어떤 필터와 더 유사한지 판별합니다.

프로그램은 두 가지 모드를 제공합니다.

- **모드 1**: 사용자가 직접 3x3 필터와 3x3 패턴을 입력하여 판별
- **모드 2**: `data.json` 파일을 불러와 여러 패턴을 자동 분석하고 성능까지 측정

---

## 1. 프로젝트 개요

NPU(Neural Processing Unit, 신경망 처리 장치)의 핵심 연산 중 하나인  
**MAC 연산**을 단순화하여 구현한 콘솔 기반 시뮬레이터입니다.

패턴과 필터를 같은 크기의 2차원 행렬로 두고,  
각 위치의 값을 곱한 뒤 모두 더한 점수를 계산합니다.

즉, 아래와 같은 방식으로 동작합니다.

score = Σ(pattern[r][c] × filter[r][c])


계산된 점수를 비교하여:

- `Cross` 필터 점수가 더 높으면 `Cross`
- `X` 필터 점수가 더 높으면 `X`
- 두 점수가 거의 같으면 `UNDECIDED` 또는 판정 불가

로 처리합니다.

---

## 2. 주요 기능

### 2.1 사용자 입력 기반 분석
사용자가 직접 다음 데이터를 입력할 수 있습니다.

- 필터 A (3x3)
- 필터 B (3x3)
- 패턴 (3x3)

입력 후 각 필터와 패턴의 MAC 점수를 계산하고,  
어느 필터가 더 유사한지 판정합니다.

---

### 2.2 JSON 기반 자동 분석
`data.json` 파일에 저장된 필터와 패턴 데이터를 읽어  
여러 테스트 케이스를 자동으로 분석합니다.

기능:

- 필터 로드
- 패턴별 예측 수행
- 기대값과 비교
- PASS / FAIL 판정
- 실패 원인 기록
- 크기별 성능 분석

---

### 2.3 라벨 정규화
데이터에 따라 라벨 표기가 다를 수 있으므로,  
프로그램 내부에서 라벨을 정규화합니다.

정규화 규칙:

- `"+"`, `"cross"` → `"Cross"`
- `"x"`, `"ex"` → `"X"`
- 빈 값 또는 `None` → `"UNDECIDED"`

즉, JSON 데이터에서는 `cross`, `+`, `x`, `ex` 같은 값이 섞여 있어도  
프로그램이 자동으로 통일해서 처리합니다.

---

### 2.4 성능 측정
행렬 크기별로 MAC 연산 평균 시간을 측정합니다.

측정 방식:

- `time.perf_counter()` 사용
- 기본 10회 반복
- 평균 실행 시간을 밀리초(ms) 단위로 계산
- 입출력(I/O) 시간 제외, 연산 구간 중심 측정

## 6. 모드 설명

---

### 6.1 모드 1: 사용자 입력 (3x3)

#### 기능
사용자가 직접 3x3 필터 2개와 3x3 패턴 1개를 입력하여  
MAC 점수를 계산하고 결과를 판정합니다.

#### 입력 형식
각 줄에 **숫자 3개**를 공백으로 구분하여 입력합니다.

예시:

1 0 1

0 1 0

1 0 1


#### 동작 절차
1. 필터 A 입력
2. 필터 B 입력
3. 패턴 입력
4. 각 필터와 패턴의 MAC 점수 계산
5. 평균 연산 시간 출력
6. 더 높은 점수를 얻은 필터 기준으로 판정

#### 판정 기준
코드에서는 `epsilon = 1e-9`를 사용합니다.

- `|A 점수 - B 점수| < 1e-9` → 판정 불가
- `A 점수 > B 점수` → 필터 A
- `B 점수 > A 점수` → 필터 B

#### 출력 예시
A 점수: 5.0

B 점수: 3.0

연산 시간(평균/10회): 0.012 ms

판정: 필터 A (Cross 등)


---

### 6.2 모드 2: `data.json` 분석

#### 기능
`data.json` 파일에 저장된 필터와 패턴을 자동으로 분석합니다.

#### 처리 순서
1. `data.json` 로드
2. `filters` 항목 읽기
3. 필터 라벨 정규화
4. `patterns` 항목 읽기
5. 각 패턴의 크기에 맞는 필터 선택
6. MAC 연산 수행
7. 예측값(`Cross`, `X`, `UNDECIDED`) 계산
8. 기대값(`expected`)과 비교
9. PASS / FAIL 집계
10. 크기별 성능 분석 출력

## 7. 코드 기준 `data.json` 구조 설명

이 프로그램은 `data.json`에서 아래 구조를 기대합니다.

### 7.1 최상위 구조
{
"filters": { ... },

"patterns": { ... }

}

즉, 최상위에는 반드시 다음 두 키가 있어야 합니다.

- `filters`
- `patterns`

---

### 7.2 `filters` 구조

`filters`는 크기별 필터 묶음입니다.

예시:
"filters": {

"size_5": {

"cross": [...],

"x": [...]

},

"size_13": {

"+": [...],

"ex": [...]

}

}


#### 설명
- `"size_5"` : 5x5 필터 세트
- `"size_13"` : 13x13 필터 세트
- 하위 키는 필터 라벨
  - `"cross"` 또는 `"+"` → 내부적으로 `"Cross"`
  - `"x"` 또는 `"ex"` → 내부적으로 `"X"`

즉, 필터 이름은 꼭 `cross`, `x`일 필요는 없고  
코드의 `normalize_label()` 규칙에 맞으면 됩니다.

---

### 7.3 `patterns` 구조

`patterns`는 테스트할 입력 패턴 목록입니다.

예시:

"patterns": {

"size_5_1": {

"input": [...],

"expected": "cross"

},

"size_5_2": {

"input": [...],

"expected": "x"

}

}

#### 설명
- 패턴 키 이름 예: `"size_5_1"`
- 코드에서는 이 이름을 `_` 기준으로 나누고,
  두 번째 토큰을 이용해 필터 크기를 추출합니다.
- 즉:
  - `"size_5_1"` → `"size_5"` 필터 사용
  - `"size_13_2"` → `"size_13"` 필터 사용

#### 주의
패턴 키는 **반드시 `size_숫자_번호` 형태를 따르는 것이 안전합니다.**

예:

- `size_5_1`
- `size_5_2`
- `size_13_1`
- `size_25_3`

## 9. data.json 작성 시 주의사항

현재 코드 기준으로 data.json을 작성할 때는 아래 사항을 지켜야 합니다.

### 9.1 최상위 키가 있어야 함
반드시 아래 두 키가 존재해야 합니다.

filters

patterns

없으면 JSON 분석 모드가 정상 동작하지 않을 수 있습니다.

### 9.2 패턴 이름 규칙을 맞춰야 함

패턴 키는 다음 형식을 따르는 것이 안전합니다.

size_크기_번호

예:

size_5_1

size_5_2

size_13_1

코드가 패턴 이름에서 크기를 추출해

해당 크기의 필터(size_5, size_13)를 찾기 때문입니다.


### 9.3 필터와 패턴 크기가 일치해야 함

예를 들어:

size_5 필터는 5x5 행렬이어야 함

size_5_1 패턴도 5x5 행렬이어야 함

크기가 다르면 연산 과정에서 오류가 나거나 FAIL 처리될 수 있습니다.


### 9.4 라벨은 정규화 규칙에 맞아야 함

다음 값들은 같은 의미로 처리됩니다.


cross, + → Cross

x, ex → X


## 10. 핵심 함수 설명

normalize_label(label)

라벨 문자열을 표준 형태로 변환합니다.


예시

"+" → "Cross"

"cross" → "Cross"

"x" → "X"

"ex" → "X"

None 또는 빈 값 → "UNDECIDED"

mac_operation(pattern, filter_mat)

두 행렬의 MAC 점수를 계산합니다.


동작

같은 위치의 원소끼리 곱한 뒤 모두 더합니다.

score = Σ(pattern[r][c] × filter[r][c])

반환값

float

measure_performance(n, loops=10)

n x n 크기의 더미 행렬을 생성하여

MAC 연산 평균 시간을 측정합니다.

반환값

평균 실행 시간(ms)

input_matrix(size)

사용자로부터 size x size 행렬을 입력받습니다.

특징

줄 수 검증

열 수 검증

숫자 변환 검증

오류 시 재입력 유도

## 11. 판정 기준

프로그램은 두 필터와의 점수를 비교해 결과를 정합니다.

모드 1

|A - B| < 1e-9 → 판정 불가

A > B → 필터 A 선택

B > A → 필터 B 선택

모드 2

Cross 점수 > X 점수 → Cross

X 점수 > Cross 점수 → X

차이가 매우 작으면 UNDECIDED

정확한 동점 처리 기준은 코드 구현 방식에 따라 달라질 수 있으므로,

실제 제출 전에는 테스트 환경에서 먼저 확인하는 것이 좋습니다.

## 15. 한계점

이 프로젝트는 학습용 시뮬레이터이므로 몇 가지 한계가 있습니다.

### 15.1 실제 NPU와는 다름
실제 NPU는 대규모 병렬 처리, 메모리 최적화, 저정밀 연산 등을 활용하지만  
이 프로그램은 단순한 2차원 행렬 MAC 연산만 흉내 냅니다.

### 15.2 노이즈 대응이 약함
패턴에 잡음(noise)이 많으면 단순 점수 비교 방식만으로는  
정확한 분류가 어려울 수 있습니다.

### 15.3 필터 수가 제한적임
현재 구조는 사실상 `Cross` 계열과 `X` 계열 비교에 최적화되어 있습니다.  
다른 도형 분류로 확장하려면 데이터 구조와 판정 로직을 함께 수정해야 합니다.

### 15.4 순수 Python 반복문 기반
성능 측면에서 대형 행렬 처리에는 비효율적일 수 있습니다.

## 18. 참고: 현재 코드에서 중요한 포인트

현재 코드 기준으로 특히 중요한 부분은 아래입니다.

1. `normalize_label()`이 라벨을 표준화함
2. `mac_operation()`이 핵심 MAC 계산 담당
3. `measure_performance()`가 연산 시간 측정 담당
4. 패턴 이름에서 크기를 추출해 대응되는 필터를 찾음
5. `expected` 값도 정규화 후 비교해야 정확함

즉, `data.json` 구조를 바꿀 때는  
특히 **패턴 키 이름 규칙**과 **필터 라벨 이름 규칙**이 깨지지 않도록 주의해야 합니다.
